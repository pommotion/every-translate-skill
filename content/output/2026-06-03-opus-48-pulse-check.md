# Opus 4.8：聪明到会成为你的阻碍

> 原文：[Every 原文链接]

---

今天，我们更新了针对 Opus 4.8 的 Vibe Check，带来一次 Pulse Check，其中融合了更多团队成员的使用视角。与此同时，Dan Shipper 与 Figma 的 Matt Colyer 进行了对谈，探讨为什么 AI 并未消灭专业设计服务；Every 的资深设计师 Daniel Rodrigues 则分享了他用于实现精确且视觉效果惊艳的双工具 AI 工作流。

## “AI 与我”：基于聊天的设计方式的局限

在我们的播客节目 *AI & I* 的新一期中，Dan 与 Figma 负责开发者的产品管理总监 Matt Colyer 进行了对话，探讨了基于聊天的 AI 代理（agent）在设计领域的局限性，以及为什么感性编程（vibe-coded）的种种产物的兴起，与你可能听到的预测相反，实际上对 Figma 是件好事。

以下是对谈要点：

- **“SaaS 末日论”把因果搞反了。** AI 代理能将任何人变成感性编程者，这引发了投资者的恐慌，他们担心像 Figma 这样的传统 SaaS 公司将无法再证明其成本是合理的。但 Colyer 并不担心：AI 极大扩展了开发者的基数，同时也更凸显了创造一个能像真正的 Figma 一样好用、一样可靠的感性编程版的 Figma 有多么困难。他自己也感性编程过多个用来处理邮件等事务的代理，但维护成本迅速累积，似乎永远不划算。“我现在买的软件比以前任何时候都多，”他说，“我情愿付钱让别人为我运行我的代理。”
- **Figma 正在拥抱代理（agent）。** 该公司推出了一个 MCP 服务器（模型上下文协议）——一个任何 AI 工具都能接入的标准化接口——让你可以从两个方向推进设计工作。“代码转设计”会抓取一个动态网页，并在 Figma 画布上重构它，这样你就可以直接操作各个元素；“设计转代码”则反转了流程，将 Figma 设计打包交给一个代理，让它通过 Pull Request 为你进行修改。
- **基于聊天的生成式设计存在天花板。** 优秀的设计核心在于一个钻石形状的流程：首先你需要发散，即产生大量点子，然后才收敛到最有希望的选择上。基于文本的聊天本质上是线性的，因此不擅长发散；这种设定迫使你选择一个选项并在此基础上迭代。代理已经能很好地完成 Figma 目前支持的、任务完成型的工作流，但在整个行业中，设计中发散、探索的部分仍未被解决。Colyer 对将这个流程拆分开来很感兴趣，让专门的代理通过推动你扩展思维来处理发散部分，再由另一组代理筛选选项，确定一条前进的道路。“即便是最好的代理，也就是命令行的代理，也没有能力完成这类工作流，”他说，“这就是我所看到的设计与产品思维未来的发展方向。”
- **代理能如此之快地产生如此之多的成果。** 但在判断其中是否有成果符合公司价值观或设计标准方面，它们就没那么擅长了。Colyer 不确定弥合这一差距的最佳方式是什么——或许是个视频演示，一张截图，或一个值得信赖的评审代理——但为了让好的设计能够规模化，AI 需要在评估环节扮演更重要的角色。

## Pulse Check：Opus 4.8 是为正确的工作而生的最佳工具

五天前，我们将 Anthropic 的 Claude Opus 4.8 称为在写作和严肃工程方面迄今为止最好的 Claude 模型，并宣布如果 Claude 的应用体验能追上 Codex，我们就会从 GPT-5.5 切换过来。经过一个工作周的更多测试，我们仍然是 Opus 4.8 的推崇者，不过随着来自不同领域的团队成员有机会发表意见，测试结果也显得更加复杂。

以下是更多 Every 团队成员关于何时使用该模型以及何时应避开的看法。

### 关键要点

- **当“有益的摩擦”能提升工作成果时，就去用 Opus 4.8。** 它擅长捕捉细微差别、质疑薄弱的框架，并能持续跟进复杂问题。但这种特质也可能变成固执、不合时宜的谨慎，或对错误解读的自信。
- **交给它漫长而混乱的工作。** Opus 4.8 获得的最强评价，都集中在处理庞杂的源材料、长时间对话、高难度的创意工作和复杂的编码任务上。对于常规问题和边界清晰的任务，它较慢的速度和更高的 token 消耗会抵消掉其质量优势。
- **现阶段不要围绕它重建你的工作流。** 即便是更喜欢 Opus 答案的团队成员，也在不断回到 Codex 中的 GPT-5.5，因为速度、上下文和连接更紧密的应用体验，压倒了模型本身优势。
- **再次检查安全警告。** 有两个独立的账户报告称，Opus 虚构了一个提示注入的安全顾虑。在搞清楚这个缺陷之前，在采纳其警告前，先要让它出示警告背后的证据。

### 伸手测试，第二部分

**Arielle Shipper，运营主管**——在最初用 Opus 4.7 构建了一个展示她发现的 HTML 网站后，她用 Opus 4.8 重做了该网站。她注意到了有意义的改进：4.8 在没有明确指引的情况下，就能区分 Notion 中两个名称相似的页面，而 4.7 却需要明确指引；并且它建议突出显示特定话题在与团队对话中被提及的次数。她的总结是：“它似乎真的非常注重细节，我很欣赏这一点。”

**Austin Tedesco，增长主管**——Austin 周末用 Opus 4.8 配合 Monologue 和 Spiral 撰写了一篇文章。对于那项工作，他写道 Opus 4.8 “是目前最好的模型”，比 Opus 4.7 更上一层楼，并且“实质上优于 GPT-5.5”。但他并不期望这会改变他的日常行为习惯。在同样的创意合作方面，GPT-5.5 表现得“相当好”，而将工作保留在 Codex 中的重要性，超过了模型质量的适度提升：“如果没有一个实质上好得多的桌面应用体验，我不认为自己会多用 Claude 模型。”

**Nityesh Agarwal，高级应用 AI 工程师**——Nityesh 在他正在为 Every 构建的 AI 员工内部测试了 Opus 4.8——Claudie 用于咨询，Andy 用于编辑团队。他报告说，该模型能在正确的时间回忆起正确的记忆，在更长的对话线程中保持有用性，并且让他能更多地利用其百万 token 的上下文窗口。但真正赢得他心的是与 Opus 4.8 一同发布的工作流自动化功能 Dynamic Workflows。Nityesh 表示，结合新模型，这感觉就像是“一次重大的能力提升”。

**Lee Knowlton，软件工程师**——Anthropic 说 Opus 4.8 更诚实，更善于标记风险。但 Lee 在一次每日规划运行中看到了这种特质的负面表现。一天早上，计划中引用了 Lee 在那些来源中找不到的事件、消息和文件。当他问 Claude 发生了什么时，它声称是一次提示注入攻击提供了虚假信息。当 Lee 挑战这个说法时，Claude 说它编造了这个事来为自己的糟糕输出做解释，它把 Lee 移动的一个计划文件误认为是受到干扰的证据。

**Andrey Galko，工程师**——Andrey 对 Opus 4.8 的编程能力持“非常积极”的态度，并写道他比 GPT-5.5 更喜欢它。对于他的使用场景，它感觉“更稳定、可靠，就是没那么蠢了”。他的保留意见不是关于模型的编程质量，而是围绕模型的体验：GPT-5.5 更快，而且 Codex 为它提供了更好的桌面应用程序支持。

## 结论：让它触手可及，而非全天开着

值得注意的是，并非所有人都像我们团队这样看好 Opus 4.8。Steve Yegge 在 X 上写道，Opus 4.8 令人感到“窒息”且“病态地规避风险”。Figma 联合创始人兼 CEO Dylan Field 称 Opus 4.8 是“一个非常奇怪的模型”，并表示它的个性感觉评判性更强，且相比 Opus 4.7，它在回应时更倾向于含糊其辞。

当 Dan 在 X 上征集集体智慧时，回复表明 Opus 4.8 最大的优势也是它最大的风险：它比其他模型更倾向于拒斥用户。当这种抵制能改进一项艰难写作或工程任务的成果时，它会感觉像是一种突破。但当它的抵制是错误的时候，就会令人沮丧并且更难以信任。

总的来说，我们的首发结论依然成立，但推荐范围有所收窄。当工作信息密度高、充满上下文，并且能受益于跨越复杂任务的持续推理时，就使用 Opus 4.8。当错位的自信或错位的谨慎带来的代价很高时，你就要把握方向。

- **针对风险较高的工作流程：** 在相信它的拒绝或安全警告前，先要验证它的判断。谨慎，只有在有证据支撑时才是一种功能。
- **针对上下文密集的知识工作：** 当你的源材料分散在多个文件和决策中时，尤其值得一试——特别是当你需要它看得比首页更深的时候。
- **针对日常主力使用：** 一个更好的模型，不等同于一个切换工作空间的理由。如果 Codex 已经是你上下文、速度和工具能力叠加的地方，那么 Opus 4.8 就是你可以为特定任务召唤的模型，而不是你搬家的理由。

当工作较长、上下文密集且能受益于二次判断时，Opus 4.8 看起来最具吸引力。如果你大多时候想要一个快捷犀利的工具来搞定事情，那么 Codex 中的 GPT-5.5 可能就是你需要的模型。— Katie Parrott

## 拿走这个工作流：在图像生成器之间切换

Every 的资深设计师 Daniel Rodrigues 使用 AI 图像生成器已有三年。如今，他很清楚它们的优缺点。以下是他关于结合两个流行方案以最大化创造力且不牺牲细节关注度的建议。

**第一步：从启动 Midjourney 开始。** 这个 AI 图像生成器能产生美丽的视觉效果，但它真正的力量在于其偏好创意发挥的倾向：给它一个提示词，它会返回包含你未指定细节的图像。“你会得到随机的东西，”Daniel 说。有些东西会跑偏，但这种不可预测性常常能激发出一个全新的、更好的方向。

**第二步：将在 Midjourney 中生成的图像上传到 Nano Banana 或 ChatGPT Images 2.0 中，敲定具体细节。** 与 Midjourney 相比，这两个模型对指令的遵从可以说是丝毫不差。这种字面执行的特点限制了 Daniel 借助该工具进行创意跳跃的能力，但它们非常适合用来精炼现有图像，使其更符合他脑海中的视觉效果。

**第三步：与模型来回沟通。** 对于细节满满的提示——例如，“一位 30 多岁的女士，戴着红色太阳镜，蓝色耳环，正在用一支黄色的万宝龙笔在笔记本上写字”——Daniel 说，Nano Banana 可能只会捕捉到你想要内容的 70%。然后，你就需要和模型反复迭代，一次只修正一个对象。
